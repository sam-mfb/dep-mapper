Project observationsContract

Defines what a source reader can report about one selected build.

Exposes
The project boundary, public surfaces, resolved imports, operations and individual handoffs, each tied to its source. Includes evidence for unused imports, external boundaries and observations the reader could not resolve.
Owns
The stable vocabulary between the reader and the analysis. An observation describes a single occurrence. The evidence module owns any conclusion that connects several occurrences.
Used by
Dependency evidence — interprets observations
Rust project reader — implements the observation contract

Rust project readerEffect

Obtains build-scoped observations from a Rust project.

Exposes
Implements Project observations for Cargo and the Rust compiler. Its output identifies the selected project and build, the observations collected, and any failure or gap in collection.
Owns
Owns compiler and workspace access. Cargo and compiler-specific representations stay here. Third-party packages can appear as boundary endpoints.
Uses
Project observations — implements the observation contract
Used by
Mapper command — selects and runs the reader

Dependency evidenceLogic

Connects observed surfaces and handoffs into routes between project packages.

Exposes
A neutral evidence graph for one build. A package, import, use or route can be cited individually. Each hop carries its source and whether it was established, is a candidate, or ends at a boundary.
Owns
Owns the rules for connecting observations. Preserves parallel routes and distinguishes a type reference, use of a value and invocation of a method. The rules apply equally to every package.
Uses
Project observations — interprets observations
Used by
Architecture review — reads the evidence graph
Mapper command — builds the graph

Architecture reviewLogic

Attaches architectural judgments to the modules and routes they describe.

Exposes
A review document a human or LLM can author, and a reviewed map joining those labels to their evidence. This is also the document contract shared with the viewer.
Owns
The author chooses the meaning. This module checks that a label refers to evidence in the selected build, retains unlabeled subjects, and surfaces references that no longer match. It can apply a revised review to existing evidence.
Uses
Dependency evidence — reads the evidence graph
Used by
Map viewer — reads the reviewed map
Mapper command — applies the authored review

Map viewerEffect

Lets a reader explore a reviewed architecture in the browser.

Exposes
A package map with directed routes and a detail view. Readers can inspect a module’s concern, kind, public surface, dependencies and consumers, or follow a use through its supporting source locations.
Owns
Consumes the published document. Owns browser interaction, layout, selection and highlighting. TypeScript, React, Redux Toolkit and Vite belong on this side of the document boundary.
Uses
Architecture review — reads the reviewed map

Map filesEffect

Keeps the evidence, authored review and published map available between runs.

Exposes
Read and write the three project documents independently, and report missing or unreadable input. The project retains its review when evidence is regenerated.
Owns
Owns local file access for the command. The meanings of evidence and labels belong to their respective modules.
Used by
Mapper command — reads and writes project documents

Mapper commandComposition

Coordinates collecting evidence and publishing a reviewed map.

Exposes
Two user-facing operations. Collect a selected Rust build for review. Publish a map from saved evidence and an authored review.
Owns
Chooses the Rust reader, passes its observations to Dependency evidence, and saves the graph through Map files. On publication it loads the graph and review, supplies them to Architecture review, and writes the document for the browser.
Uses
Rust project reader — selects and runs the reader
Dependency evidence — builds the graph
Architecture review — applies the authored review
Map files — reads and writes project documents

How one review travels

The mapper command saves the evidence from a Rust build. A human or LLM reads that graph and authors labels for specific packages and routes. The command uses Architecture review to match those judgments to the evidence, then publishes the reviewed map. The browser can open that document on its own.

For example, two routes may connect the same packages. The reviewer can label one “adapts” and the other “incidental use.” Selecting either arrow in the published map leads to the method and handoffs that motivated that particular label.

Design choice for review. The proposal starts with a review document that can be edited outside the viewer. Whether dep-mapper should itself provide label editing or invoke an LLM is open.
