Project observationsContract

Defines what a source reader can report about one selected build.

Exposes
The capability to obtain project observations for a selected build, including source locations and collection gaps.
Owns
Defines the shared contract. Rust project reader implements it. Dependency evidence requires it. Mapper command supplies the implementation.
Used by
Dependency evidence — requires the reader contract
Rust project reader — implements the observation contract

Rust project readerEffect

Obtains build-scoped observations from a Rust project.

Exposes
An implementation of Project observations backed by Cargo and the Rust compiler.
Owns
Owns build and compiler access. Mapper command constructs the reader and injects it into Dependency evidence. A request through that contract returns observations about the selected build.
Uses
Project observations — implements the observation contract
Used by
Mapper command — constructs the reader for injection
Wiring
Rust project reader → Mapper command → Dependency evidence (shared-contract injection)

Dependency evidenceLogic

Connects observed surfaces and handoffs into routes between project packages.

Exposes
A neutral evidence graph for one build. Each package, import, use and route can be cited. Each hop carries its source and whether it was established, is a candidate, or ends at a boundary.
Owns
Requires a reader through Project observations. It asks the injected reader for observations, connects them according to the evidence rules, and returns the graph. A saved graph can be reviewed separately.
Uses
Project observations — requires the reader contract
Used by
Architecture review — reads the evidence graph
Mapper command — builds the graph
Wiring
Rust project reader → Mapper command → Dependency evidence (shared-contract injection)

Architecture reviewLogic

Attaches architectural judgments to the modules and routes they describe.

Exposes
Accepts an evidence graph, requires a source of judgments for that graph, and returns a reviewed map. Owns the review document format and the published map format.
Owns
The human or LLM authors the labels. Architecture review calls its injected judgment source, checks the returned references against the evidence, and preserves unresolved or unlabeled subjects. Mapper command supplies a small adapter over Map files to satisfy this requirement.
Uses
Dependency evidence — reads the evidence graph
Used by
Map viewer — consumes the reviewed document format
Mapper command — composes review with a judgment source
Wiring
Map files → Mapper command → Architecture review (injection through an adapter)
Architecture review → Mapper command → Map viewer (document handoff)

Map viewerEffect

Lets a reader explore a reviewed architecture in the browser.

Exposes
A browser viewer bundle with an entry page that loads the accompanying reviewed map document.
Owns
Mapper command selects this bundle and pairs it with the output of Architecture review. In the browser the viewer reads that document and owns layout, selection and evidence drill-down. TypeScript, React, Redux Toolkit and Vite belong here.
Uses
Architecture review — consumes the reviewed document format
Used by
Mapper command — takes the browser bundle for publication
Wiring
Architecture review → Mapper command → Map viewer (document handoff)

Map filesEffect

Keeps the evidence, authored review and published map available between runs.

Exposes
File access to saved evidence, an authored review document, and the files of the published map. Missing or unreadable input is reported to the caller.
Owns
Supplies the file-reading effect behind the judgment source. It reads the authored document selected by Mapper command. Architecture review owns interpretation of its contents. Map files also writes the viewer bundle and reviewed document together for publication.
Used by
Mapper command — reads and writes project documents
Wiring
Map files → Mapper command → Architecture review (injection through an adapter)

Mapper commandComposition

Coordinates collecting evidence and publishing a reviewed map.

Exposes
Collect evidence from a selected Rust build, then publish a browser map from saved evidence and an authored review.
Owns
Injects Rust project reader into Dependency evidence. For review it adapts the selected file reader to the judgment source required by Architecture review. For publication it pairs the returned map document with the viewer bundle and uses Map files to write them together.
Uses
Rust project reader — constructs the reader for injection
Dependency evidence — builds the graph
Architecture review — composes review with a judgment source
Map files — reads and writes project documents
Map viewer — takes the browser bundle for publication
Wiring
Rust project reader → Mapper command → Dependency evidence (shared-contract injection)
Map files → Mapper command → Architecture review (injection through an adapter)
Architecture review → Mapper command → Map viewer (document handoff)

Review input in this proposal

A saved review document is the common entry point for a human or an LLM. If an interactive editor or model service is added later, Mapper command can supply another implementation of the same judgment-source requirement.
